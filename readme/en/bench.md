# Embedded Key-Value Storage Benchmarks

The tables below are produced by [`redb-bench`](https://github.com/cberner/redb/tree/master/rocksdb-bench) compatible harness in [`bench/`](https://github.com/webc-site/wedb/tree/main/bench) and refreshed by CI on every push to `main`. Do not edit them by hand: they are regenerated byte-for-byte from the machine-readable run results (`node js/readme.js`).

Compared engines:

| Column | Engine | Binding |
|:---|:---|:---|
| `hash` | [wkv](https://github.com/webc-site/wedb/tree/main/wedb/wkv) | wedb's own append-only hybrid-log KV store |
| `bftree` | [wbftree](https://github.com/webc-site/wedb/tree/main/wedb/wbftree) | wedb's own ordered bf-tree index |
| `fjall` | [fjall](https://github.com/fjall-rs/fjall) | `fjall` crate, default durable mode |
| `rocksdb` | [RocksDB](https://github.com/facebook/rocksdb) | `rocksdb` crate with `OptimisticTransactionDB` |
| `sqlite` | [SQLite](https://www.sqlite.org) | `rusqlite` over a BLOB-keyed table in WAL mode |

## Benchmark Parameters

| Parameter | Setting |
|:---|:---|
| **Key Size** | 24 B |

| **Cache Size** | 4 GiB (auto-shrunk to fit physical memory) |
| **Bulk load / sorted insert scale** | 5,000,000 / 1,000,000 entries |
| **Individual / nosync / batch writes** | 50,000 / 2,500,000 / 100 batches × 1,000 |
| **Random reads / range reads** | 100,000 lookups / 50,000 × 10-element scans, median of 3 |
| **Multi-threaded reads** | 4 / 8 / 16 / 32 threads |
| **RNG seed** | 3 (identical key distribution for every engine) |

### Configuration & Methodology Notes

- **Workload parity**: every engine receives the exact same key/value distribution generated from one seed, so rows are directly comparable across columns.
- **Durability**: all write sections except `nosync writes` perform durable per-transaction commits. The `nosync` section disables per-commit fsync (SQLite maps it to `synchronous = OFF`, RocksDB to `set_sync(false)`) and durable writes are restored afterwards.
- **Process isolation**: each column runs in its own subprocess under a wall-clock budget. A column that fails, panics or exceeds the budget is recorded as a whole-column `N/A` with its status and exit detail in the notes; it never silently disappears from the table.
- **Best-in-row** values are bolded (ties included). Throughput rows are higher-is-better; `len()` and the two size rows are lower-is-better.
- **`len()`** mixes counting semantics across engines (metadata counter vs full-keyspace scan), so it is a cost-of-counting figure, not a performance conclusion.
- **`pop`** is measured through a sampled removal and extrapolated to the full workload, because a complete pop pass would dominate the runtime; the sampled count is reported in the machine-readable result.
- **Sizes** are the recursive byte total of the engine's data directory (WAL, segment and manifest files included), before and after the engine's own compaction/vacuum step.
