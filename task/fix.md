# 任务执行流程

以 task/todo 为核心生命周期。每个任务独立开一个执行子代理，单代理单任务：

task/todo/ → 甄别 → 如果有道理进 task/ing/（执行开发）→ git mv → task/done/
                  → 如果无道理驳回 → git mv → task/reject/

---

## 0. 领票甄别（todo 甄别）

对 task/todo/ 中的工单逐一甄别，必须逐点现码复跑，不得只读票面背书：
1. 真实性：票面所引 C# 一手形态锚（garnet 现树文件:行号）与 rust 现状锚（wedb 现码）双侧亲验成立，非幻觉、非对上游的误读
2. 非重复非灭失：未被既有在册偏差条目（doc/zh/deviations.md）与其他池票据（ing/done/reject）覆盖或并案
3. 架构合规：执行方案符合单向分层、单套机制、无过度设计、无假桩
4. 可执行度：改动点具体可落、步骤最小、验证方式闭环
5. 格式纯粹：纯文本无加粗/表格/横线，双侧代码路径齐全

分流操作（使用 git mv 保留历史）：
- 有道理（通过）：git mv 至 task/ing/，票面顶部注明「甄别结论：通过」与定级，派子代理在沙箱开发修复
- 无道理（驳回）：git mv 至 task/reject/，顶部注明拒绝结论与确凿反证（双侧行为核实与架构依据）
- 执行期发现判据灭失（现码已自证收口、上游已修复）的，回退 task/reject/ 并注记原因

---

## 1. 领取与锁票

任务开始之前，必须在主目录将任务文件状态标记为进行中：
git mv task/todo/<模块>-<问题简述>.md task/ing/<模块>-<问题简述>.md

禁止跨任务贪多，一个子代理只认领一个任务。

---

## 2. 沙箱隔离开发

运行 ./fork.sh 在 /tmp/fork 开专属 worktree 独立开发：
- 严格遵循 ./.agents/skills/transpile/SKILL.md 与 ./.agents/skills/rust_review/SKILL.md
- 严格对标 c#，确保全链路只有一套机制，删除死代码与冗余逻辑
- 测试尽量放到 tests/ 目录下，避免在 src/ 中堆砌测试代码
- 测试尽量对标 c#（garnet/test/...），严禁编造无实际依据的假 mock 或未闭环竞态等垃圾测试
- 子代理只运行 cargo check 验证编译，禁止运行 ./test.sh 和 ./sh/clippy.sh（避免多代理互锁）

---

## 3. 合并与防冲突

合并前准备：
1. 先在 worktree 内提交自身改动
2. 拉取/合并主目录最新 commit，解决冲突
3. 按 rust_review 再次审查：清理合并引入的死代码与重复实现，保持单套机制
4. 合并代码至主目录，删除对应 worktree

---

## 4. 任务归档

代码合并完成后，在主目录将任务文件移动至已完成：
git mv task/ing/<模块>-<问题简述>.md task/done/<模块>-<问题简述>.md

归档提交须含票面终态注记(合入哈希+收口形态),纯 mv 归档视为未尽

---

## 5. 主代理集成门禁

- 调度执行子代理并发推进，同时在跑的子代理最多 5 个；跑满 5 个时须等有空位再派新棒
- 子代理合并到主目录后，由主代理统一运行 ./test.sh 与 ./sh/clippy.sh
- 测试慢，跑完后检查是否有新子代理在此期间完成合入；若有，再次运行
- 遇红用例，开新 issue 重新走提案、审核、执行闭环修复
- 循环推进，直至全部任务归档至 task/done/
