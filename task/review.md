# 审查与提案流程

单议题单代理，审查只审不改代码，不跑长测试，快审快出。

全局生命周期：
线索发现 → 起草 (task/issue/) → 审核 (task/todo/ 或 task/reject/) → 执行 (task/fix.md 接管: todo → ing → done)

## 审查步骤与工作流

### 阶段一：线索定位与事实确证

审查输入：
- 对照 ./garnet 源码与工程代码对账
- 核验 ./doc/zh/deviations.md 既有架构设计偏差登记，避免重复提报已知裁决
- 核验 ./doc/zh/db.md 数据库隔离、多租户命名空间与虚拟库架构
- 核验 ./doc/zh/collection.md 集合类型自适应分层与双态存储规范
- 运行 ./js/check.js 扫描缺失与重复定义
- 参考 ./.agents/skills/transpile/SKILL.md 与 ./.agents/skills/rust_review/SKILL.md
- 集成测试、回归测试或压测异象

定位准则：
- 优先用 codegraph explore "<符号名或问题>" 定位，避免无目标全局翻找
- 严禁凭空脑补，必须核对 Rust 现状与 C# 源码对应逻辑
- 辨别两类代码：
  1. 真实缺陷：契约分叉、漏项、竞态、死锁、状态脱节、panic 面、内存记账失真、假桩未接线
  2. 既定改良：项目规范明定的自研改良（如共享单存储多库隔离、物理键前缀编码、秒级换号清库、自适应分层集合、无锁哈希、无旧兼容、嵌套配置、零全局字典），严禁将架构改良误报为缺陷

### 阶段二：提案起草

每个独立问题单独立项，新建文件：
task/issue/<模块>-<核心问题用中划线命名>.md

格式铁律：
- 简洁纯文本（严禁 Markdown 表格、严禁加粗、严禁横线分隔符）
- 必须标明 Rust 侧具体文件与函数路径
- 必须标明 C# 侧对应文件与函数路径

内容模版：
<一句话核心问题标题>

问题分析：
1. Garnet 契约对齐（C# 原型行为与协议约定）
2. 工程现状确证（Rust 现有实现路径与代码缺陷）
3. 逻辑危害确证（并发/数据丢失/Panic/资源泄露等实际危害）

涉及代码：
rust 文件与函数：
<相对路径>:<类型或函数>

对应 c# 文件与函数：
<相对路径>:<类型或函数>

精炼执行方案：
1. <具体改动点 1>
2. <具体改动点 2>
3. <测试验证点>

### 阶段三：独立方案审核

每个 issue 分配独立的审核子代理，只判定不改业务代码：

判定标准：
1. 真实性：缺陷是否真实存在，非 AI 幻觉，非对上游逻辑的误读
2. 架构纯洁与单向分层：严格单向依赖，底层绝不反向依赖上层，零全局可变状态，彻底无视向下兼容，无旧数据迁移代码，无专有平台绑定
3. 单机制与反过度设计：全链路一套机制，严禁过度设计，严禁引入双重机制或过渡胶水，内部结构体字段直接访问避免多余包装
4. 数据面零开销承诺：数据面热路径零额外堆分配、静态分派避免虚表、控制面锁不渗透进数据面
5. 方案可落度：执行方案路径清晰、步骤最小化、具备闭环验证方式
6. 格式纯粹度：纯文本无加粗、无表格、无横线分隔符，代码路径双向齐全

分流操作（使用 git mv 保留历史）：
- 拒绝：
  git mv task/issue/<文件名>.md task/reject/<文件名>.md
  在文件顶部注明拒绝结论与确凿的反证原因（C# 行为核实与架构依据）
- 通过：
  git mv task/issue/<文件名>.md task/todo/<文件名>.md
  在文件顶部标记审核结论：通过，并整理优化执行方案，供 task/fix.md 直接消费

## 通用审查核心维度

不绑定特定模块或局部函数，按系统工程分层模型划分为五大板块共 9 大正交维度，架构治理先行定调，底层并发与持久基座（底层存储）紧随其后，再逐级递进至执行效能、系统韧性与外层契约，全仓通用适用：

### 板块 1：架构设计与单一机制

- 分层单向依赖与编译隔离：依赖关系严格单向（上层协议与网络依赖核心存储引擎，存储引擎依赖底层原语与设备抽象），底层绝不反向依赖上层；保持 crate 独立编译边界，严禁跨层循环依赖或全局反向打洞
- 控制面与数据面严格解耦：数据面热路径（CRUD / 扫描）保持零额外分配、零锁争用、静态分派与单次遍历；控制面冷路径（换号、配置热更、检查点、平滑停机）采用明确串行互斥，控制面逻辑与锁绝不渗透污染数据面
- 静态分派与零成本抽象：热路径严禁滥用动态虚表分派，优先采用泛型静态分派或静态枚举分发；能在编译期计算的常量与逻辑严禁拖到运行时动态计算
- 全链路唯一机制：同类功能只保留一套最优解，坚决清除并存的双机制与过渡适配层；项目确立的自研存储架构为全仓唯一法定实现，严禁引入历史遗留的多套冗余机制
- 零全局可变状态与清晰所有权：彻底杜绝全局可变字典与单例容器，状态一律下沉为连接私有上下文或明确的宿主所有权容器；消除无谓克隆与多余引用计数包装，借用生命周期显式收口
- 零死代码与假桩清退：清理未引用的孤儿逻辑，彻底删除无实际业务连通的空占位桩函数；不向下兼容旧版本格式，不保留废弃数据迁移代码，清理专有平台私有依赖
- 概念抽象单一真源：全局常量、枚举、控制标记统一在基座定义，严禁各处散落裸类型与魔数
- 接口最小暴露与字段直取：严格收敛公开作用域，禁止无意义二次导出；模块内部专属结构体直接公开内部字段，严禁编写无业务价值的多余包装函数，坚决杜绝过度设计

### 板块 2：并发控制与数据安全（底层存储基座）

#### 2.1 并发互斥与时序竞态
- 加锁目标准确性：细粒度锁必须命中仲裁主锚点（如哈希主桶而非溢出桶），读改写与事务锁模式精准匹配，严禁锁脱节导致互斥失效
- 锁序与死锁预防：全仓定义确定性加锁层级顺序，杜绝交叉加锁与反向加锁；执行期严禁跨异步操作持有同步锁
- 纪元屏障与安全窗口：纪元并发保护进出时机精准，临界区保护与底层内存访问生命周期严格对齐，严禁持纪元守卫执行阻塞式磁盘 I/O 导致纪元滞后
- 原子操作与乱序防御：杜绝滥用宽松内存序，消除检查与修改之间的时序竞态窗口（TOCTOU）；多字数据布局必须遵守发布屏障，防止读者观察到半字撕裂态
- 元数据换号串行互斥：涉及全库换号、全局映射切换的控制面操作，必须通过显式串行锁或原子 CAS 严格互斥，保证临界区不撕裂、不重入、杜绝死锁
- 会话单写者上下文纪律：连接私有上下文标量仅限单写者串行更新，跨任务或跨线程共享长持有时严禁并发篡改会话状态

#### 2.2 持久可靠与崩溃一致
- 日志安全推进与截断：预写日志安全截断点必须严格受持久化检查点覆盖保护，严禁换页未落盘即主动截断；日志追加失败必须上抛拒绝写入，防止主从状态发散
- 恢复与重放幂等性：检查点加载与增量日志重放必须幂等，严格按版本标记校验跳过已持久化历史，严禁重放导致重复递增或状态错位
- 偏序回收屏障：物理删除必须遵守偏序屏障（先摘除上层索引并度过安全纪元，再执行底层物理紧缩与丢弃），杜绝脏读与悬挂指针
- 真实落盘承诺与扇区对齐：底层文件写出必须满足硬件扇区对齐要求，各平台 fsync 语义不虚标，已持久化最高安全水位真实生效，防断电数据丢失
- 检查点快照与辅助存储协同：主存储引擎快照与外挂分层存储文件的快照时序严格对齐；物理文件删除必须受安全纪元与延迟到期队列保护，严禁提前删除留下崩溃窗口

### 板块 3：资源开销与执行效能

#### 3.1 零拷贝与单次迭代
- 借用零拷贝优先：只读路径优先暴露切片借用视图与闭包回调，消除热路径多余的堆内存分配
- 单次遍历收敛：流式单次遍历合并，严禁多轮重复循环、中间多余集合转换与无效克隆；热路径键值比对优先利用硬件 SIMD 加速
- 精简异步捕获：异步闭包与后台任务按需精确捕获必要字段，严禁整引用盲目捕获或深拷贝大对象
- 批量写入折叠：批量操作单次折叠条带锁、单次进入纪元、集中命中页缓存与元数据一次性维护
- 上下文前缀零堆分配：频繁调用的租户与前缀缓冲优先在栈上构造定长视图，热路径调用与前缀剥离消除堆内存开销
- 集合点查与扫描切片借用：复合对象与分层索引的点查均暴露借用视图，范围扫描采用流式回调，消除大集合整包反序列化读放大

#### 3.2 内存记账与资源闭环
- 记账真实性：复合对象、分层存储与系统元数据内存统计不漏报、不虚报，容量限额与驱逐真实生效
- 资源生命周期收口：会话、连接、临时分段、远端对象句柄随宿主析构安全释放，无孤儿资源泄漏
- 消除无界开销：网络缓冲、复制积压队列、全局缓存预算与后台任务队列必须具备背压与高低水位限制
- 双维度防抖动与自适应分层：动态分层存储严格遵守元素数量与内存体积双门限迟滞死区，升阶采用宽松触发，降阶采用严苛触发，彻底消除临界增删抖动
- 索引与页缓存预算耗尽兜底：底层索引与页缓存触达全局内存预算硬顶时显式向上报错，上层平滑回退，严禁无界抢占或死锁
- 槽位复活与日志空洞收敛：失效记录按尺寸分桶管理并优先原位复活分配，避免追加日志产生永久物理空洞与无界膨胀
- 扩容分裂死条目过滤：索引分块扩容与数据迁移时，严格过滤已物理截断的死条目，禁止向新索引双写无效历史，杜绝索引槽位膨胀

### 板块 4：系统韧性与状态闭环

#### 4.1 边界防御与异常安全
- 算术下溢与溢出保护：计数器、指标采样、时间差值计算优先采用饱和算术运算，彻底消除减法下溢崩溃；超大过期时间做边界钳制，防时间溢出导致连接中断
- 边界兜底保护：除零、数组越界、空集合取值、特殊浮点数（非法 NaN 与无穷大）显式安全守卫；参数越界与非法边界输入必须严格拦截
- 异常收敛与透明传播：生产路径严禁使用未受控的断言与拆包（unwrap/panic），底层存储与系统错误通过统一错误类型透明转发，禁止静默吞错
- 大键 O(1) 计数规约：全部集合与索引的计数命令必须严格直读标量，带到期时间的元素通过惰性堆序剔除或水位前移按纪元分摊，严禁为取数量扫描底层全量数据页
- 物理存储单页尺寸钳制：单条记录对齐物理尺寸不得超出存储分配器的单页容量硬上限，复合对象升阶前必须做单页容纳性前置校验

#### 4.2 状态闭环与多路径一致
- 多路径行为同构：内存直读快路径与磁盘异步回读慢路径、单条与批量操作行为严格一致，严禁分支遗漏钩子或版本推进
- 删空自愈与生命周期：集合元素归零原子写墓碑、清理随键元数据与 TTL，原子销毁底层分层树与外部文件，严禁悬挂空对象与孤儿存储
- 版本与观察者栅栏：用户键变更（包含存在键修改与缺席键删除）全路径无条件递增观察者版本，防止事务与 WATCH 机制脱节
- 状态机单向闭环：显式枚举状态转移，状态转换无悬挂死状态，无非法状态旁路
- 会话上下文与隔离屏障：认证重置、租户切换或协议升级时上下文彻底解绑或安全拦截，严防跨租户数据泄露与孤儿状态残留
- 多租户物理隔离与前缀注入：全仓物理键统一定义多租户前缀编码，读写链路全流程强制携带租户上下文，全局扫描与键空间遍历精准剥离前缀，实现单物理存储下的强逻辑隔离
- 秒级换号与清库路由闭环：清库、清租户、换库操作优先采用 O(1) 路由单元格原子换号，旧映射压入后台延迟回收队列，严禁同步逐键删除导致长时间阻塞与写放大
- 订阅通道与权限隔离闭环：发布订阅通道与访问控制规则必须按命名空间折叠隔离，对外回显剥除内部前缀，规则变更通过全局代数递增向会话广播即时收敛
- 多库分布式槽位离散保证：多逻辑库哈希槽位映射必须满足同库同槽以保证事务原子性，同时保证不同库均匀雪崩离散

### 板块 5：契约对标与工程纯洁

#### 5.1 协议语义与契约对标
- 命令处理与参数解析：参数个数、类型校验、回显格式严格对标协议规范
- 默认值与哨兵值映射：配置默认值、超时值（0、负数、无限大等特殊语义）严防映射反向或遗漏
- 错误契约对齐：错误帧类型、错误码及前缀符合客户端协议预期
- 边界输入响应：空键、超长键、特殊字符、转义序列等边缘场景处理合规
- 数据结构响应逐字节全等：标准数据结构对外响应严格对齐协议契约，内部多态存储（内存态与分层态）对同一数据集返回逐字节全等应答
- 自由切库契约：切库操作原生支持 64 位大整数库 ID，单机与集群模式均支持无限制自由切库，彻底消除历史限制

#### 5.2 控制面连通与运行生命周期
- 配置全链路真接线：命令行参数与配置文件选项必须直达对应消费组件，严禁只读不用的假旋钮
- 平滑关停与在途排空：关停流程必须先断新连接、排空在途请求、等待刷盘落地，防数据丢失与阻塞挂起
- 实例独占与安全边界：数据存储目录建立独占文件锁守护，防范多进程并发双写破坏存储
- 度量采集轻量无害：慢日志、性能指标、延时采样无锁竞争热点，时钟读取保证单调递增

## 审查红线清单

出现以下情况直接判定为不合格或予以驳回：

1. 凭空臆测与虚假缺陷：未经原型行为或工程代码确认，凭空捏造不存在的缺陷或协议分歧
2. 假桩与假测试：为跑通检查使用占位函数、未闭环 mock、无断言测试
3. 引入双机制：已有成熟机制，又新建一套并存逻辑或引入过渡胶水
4. 破坏架构改良：试图改回上游冗余设计（如独立存储实例、独立对象库、独立日志、向下兼容、旧数据迁移、动态加载模块）
5. 粗暴修改规范：用 allow 压制警告，通过修改注释绕过代码检查
6. 格式违规排版：包含加粗、表格、横线分隔符等纯文本违规元素
