# 任务需求清单

## 1. 代码下沉与抽象复用（设计模式、重复流程、泛型）
- 目标：审查 wedb/wedb_standalone/src 代码，将可复用的核心逻辑下沉至基础/下沉模块（如 wnode）
- 隔离约束：wedb 和 wedb_standalone 相互独立，严禁产生相互依赖
- 落地要求：
  - 将节点存储编排服务（如 NodeService<D: Device>）下沉至 wnode::service
  - 通过泛型 D: Device 统一约束，零成本抽象
  - 收敛存储引擎与 AOF 监听器端口绑定、GC 触发、会话管理和重放恢复流程

## 2. 集群模块（wedb/wedb/src）与下沉模块打通及清理
- 目标：打通 wedb/wedb/src 与下沉模块（wnode、wtxn、wpubsub 等），清理重复实现
- 落地要求：
  - 接入 wnode 下沉的服务治理与通信切面
  - 清理 wedb/src 内部重复定义的结构体、配置、状态枚举与协议处理
  - 确保集群节点装配统一基于下沉底座

## 3. 文档注释与 C# 源码对标（./js/check.js 规范）
- 目标：对照 ./garnet/ 源代码进行 code review，检查函数文档注释完整性
- 规范依据：参考 .agents/skills/transpile/SKILL.md
- 落地要求：
  - 保证 Rust 函数与 Garnet C# 代码的精准映射
  - 注释严格采用规范格式：/// 在 garnet 中的相对路径:函数名
  - 修复缺失的映射文档注释，确保通过 ./js/check.js 检验

## 4. 重复逻辑清理与单一策略对标
- 目标：避免多套策略与机制，彻底对标 ./garnet/ 官方实现
- 落地要求：
  - 坚决杜绝 AI 坏味道（重复定义、重复代码不拆分复用、多套冗余分支）
  - 跨模块通用逻辑合理拆分至公共层复用，一处定义
  - 数据格式与协议处理保持单一权威路径，不搞多格式冗余

## 5. 集成测试拆分与废话测试清理
- 目标：所有集成测试从 src 抽离至 tests 目录，并严格对标 ./garnet/test
- 落地要求：
  - src 目录下禁止包含集成测试，仅保留必要的局部单元测试
  - 对标 ./garnet/test/standalone 与 ./garnet/test/cluster 目录用例
  - 全面清理 AI 自动添加的无意义虚假断言与废话测试，仅保留对标 C# 的有效测试

## 6. 严禁二次导出
- 目标：消除跨 crate 的二次导出（pub use 第三方库或同工作区其他模块）
- 落地要求：
  - 凡需要依赖的模块，均通过 cargo add 直接添加到各自的 Cargo.toml
  - 代码内部直接 use 具体依赖 crate，禁止通过中间 crate 进行 pub use 转导
  - 保持各模块接口暴露的低耦合、高内聚

## 7. 子代理闭环迭代与持续审查优化
- 目标：开启子代理对上述所有问题持续思考与审查
- 落地要求：
  - 遵循 .agents/skills/rust_review 代码规范
  - 子代理做出改动后必须运行 ./test.sh 验证
  - 只要子代理产生改动，继续开新子代理进行循环审查，直到子代理确认完备达到生产标准
