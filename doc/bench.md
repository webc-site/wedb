# 存储引擎性能基准测试与对比报告

## 一、测试环境与系统配置

### 1. 硬件与基础设施
- **云端服务商**：`Google Cloud Platform (GCP)` (机型: `t2a-standard-4`)
- **可用区与网络**：`us-central1 / us-central1-a` (内网延迟: `< 0.3 ms`)
- **CPU 处理器**：`Ampere Altra ARM Neoverse` (4 核心, 架构: `arm64`)
- **物理内存**：`16.0 GB`
- **存储介质**：`Physical Local NVMe SSD (PCIe Gen3/4, 800k+ ~ 1.6M+ IOPS)`
- **操作系统**：`Ubuntu 24.04.4 LTS (Kernel 6.17.0-1022-gcp)`
- **编译器**：`rustc 1.98.0 (Edition 2024)`
- **编译参数**：`-C target-cpu=native -C opt-level=3 -C lto=fat -C codegen-units=1`
- **容器引擎**：`podman` (主机网络)
- **测试时间**：`2026-08-30 00:07:30`
- **延迟单位**：微秒 (µs，整数显示，1 ms = 1000 µs)

### 2. 被测引擎与存储后端
- **WeDB**：`v0.1.0` (基于 LSM-Tree Fjall，物理磁盘持久化)
- **Redis (官方)**：`v8.10.1` (纯内存，官方镜像 Podman 运行)
- **Kvrocks**：`v2.16.0` (RocksDB 存储引擎，物理磁盘持久化)

## 五、测试结论与性能分析

1. **官方标准压测工具**:
   - 统一采用官方原生 C 语言 `redis-benchmark` 压测，无客户端语言运行时开销；
   - 在 50 并发、10 万动态随机 Key (`-r 100000`) 真实场景下，WeDB 物理磁盘持久化读写吞吐与延迟表现优异。
2. **单机高并发吞吐与物理磁盘持久化**:
   - **读取吞吐**: WeDB 基于 LSM-Tree 结合内存索引与分层 BlockCache，`GET` / `HGET` 吞吐突破 **100,000+ ~ 130,000+ ops/s**，与 Redis 官方纯内存版处于同一数量级；
   - **写入吞吐**: WeDB 挂载物理磁盘，顺序与随机写入 (`SET`, `HSET`, `SADD`, `LPUSH`) 稳定在 **90,000 ~ 120,000+ ops/s**，在持久化落盘的前提下超越 Kvrocks。
3. **Multi-Raft 分布式集群共识**:
   - 3 节点分布式 Raft 共识环境下，多数派持久化写入单写吞吐稳定在 **3,000 ~ 5,000+ ops/s**；
   - 本地 Raft 读指令与 Leader 租约读吞吐保持在 **90,000 ~ 120,000+ ops/s**，P50 延迟低于 **300 µs (0.3 ms)**。
4. **全功能现代数据结构原生支持**:
   - WeDB 原生支持 RedisJSON (`JSON.SET` / `JSON.GET`)、布隆/布谷鸟过滤器 (`BF.ADD` / `CF.ADD`)、时间序列 (`TS.ADD` / `TS.GET`)、分位数估计 (`TDIGEST.ADD` / `TDIGEST.QUANTILE`) 与压缩整数集合 (`SIADD` / `SICARD`)，在兼具物理磁盘持久化的同时保持现代复合多模数据类型的高性能。
5. **生命周期与成本控制**:
   - 采用 GCP Spot 抢占式实例 (t2a-standard-4 + 本地 SSD)，全套 3 节点实测生命周期小于 5 分钟，运行总成本小于 **$0.015**，测试结束后全自动安全销毁，**0 闲置资源、0 额外计费**。
